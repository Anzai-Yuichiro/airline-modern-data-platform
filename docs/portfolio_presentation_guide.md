## 1. ポートフォリオとしてのコンセプトと強み

### 1.1 なぜ「航空会社（スターフライヤー）」の模擬システムなのか？
単なる「TODOアプリ」や「サンプルのECカート」ではなく、航空券予約という**「リアルで複雑なビジネスドメイン」**を題材に選定しています。
- **データ構造の複雑性**: 路線、運航便、シートマップ（座席指定）、搭乗者、決済、マイレージ計算など、実ビジネスに直結するリレーショナル構造を持つ。
- **高トラフィック＆リアルタイム性**: 空席照会やユーザーの離脱行動はリアルタイム性が高く、ストリーミングデータ基盤の強みを最大限に発揮できる。
- **ビジネス価値の可視化**: 「カゴ落ち防止」や「ファネル分析によるCVR改善」といった、企業の収益に直結するマーケティング課題を解決できる。

### 1.2 技術的なアピールポイント（差別化の源泉）

| アピール項目 | 本システムにおける実装内容 | クライアントへの提供価値 |
| :--- | :--- | :--- |
| **モダンデータスタック** | Apache Beam, Kafka, DuckDB / BigQuery, dbt | 「最新の技術スタックで、拡張性が高く属人化しないデータ基盤」を構築可能 |
| **ストリーミング＆リアルタイム処理** | ユーザー行動イベントを数秒以内にDWHへ反映 | バッチ処理のタイムラグを解消し、「今買おうとしている顧客」を逃さない |
| **dbtによるデータモデリング** | メダリオン構造（Bronze/Silver/Gold）、データ品質テスト自動化 | 分析担当者が使いやすいクリーンなマートの整備、集計ミスの撲滅 |
| **クラウド移行性 (IaC)** | ローカル（Docker）からGoogle Cloud（Dataflow/BigQuery）への移行設計 | 予算や規模に合わせたスモールスタートからエンタープライズ拡大まで柔軟に対応 |
| **フルスタック実装力** | React (UI) 〜 Node.js (API) 〜 Python (ETL) 〜 SQL (DWH) | 「画面から基盤まで一気通貫でわかるため、手戻りのない要件定義・実装」が可能 |

### 【クライアントの課題に対する提案アプローチ（営業トーク例）】

#### 相談例①: 「散在している顧客行動データを集約してリアルタイムに分析したい」
> **回答例**:
> 「本ポートフォリオのように、WebサイトのイベントログをAPI Gateway経由でメッセージブローカー（Pub/SubやKafka）に集約し、Apache Beam / DataflowでリアルタイムにDWH（BigQuery）へ流し込むパイプラインを構築できます。御社の既存サイトに軽量なJavaScriptタグを埋め込むだけで、ユーザーの行動が数秒で可視化されます。」

#### 相談例②: 「dbtを導入してSQLの属人化を防ぎ、データ品質を担保したい」
> **回答例**:
> 「本システムでは、Bronze（生ログ）からSilver（クレンジング）、Gold（分析マート）へと段階的にデータを整形するメダリオンアーキテクチャを採用しています。dbtを活用することで、主キー重複や参照整合性チェック（dbt test）を自動化し、仕様変更に強いデータマートを短期間で構築可能です。」

#### 相談例③: 「カゴ落ち（購入途中の離脱）を防ぎ、売上を向上させたい」
> **回答例**:
> 「本システムの実装例のように、『座席選択まで進んだが決済していない』ユーザーをリアルタイムに検知し、Slackやメール配信サービス、LINEへの自動通知（WebHook）をトリガーする仕組みを低コストなサーバーレス構成（Cloud Run / Cloud Functions）で実装可能です。」
